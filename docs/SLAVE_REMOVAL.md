# APP 单台删除从机（2026-10-21）

配套 APP 1.2.2（versionCode 10）、ESP32-S3 N16R8 主机固件及 ESP32-C3 从机固件。主机 PWM 仍为 GPIO4。产物已构建；本次未安装 APP、未刷写设备，蓝牙空口、掉电恢复和重新入网仍需实机验收。

## 使用

1. 连接主机，在 APP「设备」页刷新从机清单。
2. 点击目标行的「删除」，核对名称和 Mesh 地址，再点击「确认删除」。支持离线从机以及已配对但未登记槽位的从机。
3. 等待主机确认并刷新清单。出水、试泵、组网、启用配置、未对账任务及删除进行期间不允许开始删除。旧主机未声明 `remove=1` 时 APP 禁用该按钮并提示升级。
4. 显示「已收到退网确认」时，主机已收到标准 Mesh Node Reset 回复。配套新版从机会关闭阀门、清除启用状态并重启，重新发送 PB-ADV 未配网广播；重加后需再次启用配置。
5. 显示「未确认从机退网」时，只确认主机本地删除完成。离线或收不到回复的从机可能仍保存旧网络，重新添加前需要在从机本地清除 Mesh。复位/重新上电不会清除 Mesh，当前从机 USB 命令也没有本地清 Mesh 入口；不要把普通 Reset 当作恢复未配网操作。

APP 不自动重发删除请求。发送失败、30 秒未确认或断线时，刷新清单和组网状态核实；主机可能已经完成删除。

## 协议与恢复

加密 GATT 命令：

```text
mesh-remove EPOCH REQUEST ADDR_HEX CONFIRM
mesh-state EPOCH REQUEST
inventory EPOCH REQUEST
```

EPOCH、REQUEST 均为非零 uint32，地址为本主机拥有的从机单播地址。命令校验失败、忙、启动代次变化、存储异常或非本主机节点均拒绝执行。拒绝响应：

```text
REMOVE epoch=7 req=11 addr=000a reply=BUSY
```

接受后用 MESH 状态报告进展，`op` 是删除请求号，`target` 为目标地址；查询的 `req` 可以不同。APP 同时核对 epoch、op 和 target。

| phase | busy | 含义 |
| --- | --- | --- |
| REMOVING | 1 | 已保存删除日志，尝试远程 Node Reset，随后删除主机 Mesh 节点 |
| REMOVE_CLEANUP | 1 | SDK 已确认本地删除，正在清该台登记和三档标定 |
| REMOVE_DONE | 0 | 本地持久清理完成，reason=REMOTE_RESET 或 LOCAL_ONLY |
| FAILED | 1 | SDK 删除结果不确定或持久化失败；需重启主机恢复并核实 |

远端等待上限 5 秒，SDK 本地删除等待上限 10 秒。只有目标地址、当前阶段匹配的回调才推进状态。`delete_node_with_addr` 对应 `DELETE_NODE_WITH_ADDR_COMP`，不使用删除未配网候选的 `DELETE_DEV_COMP`。

NVS 新增独立的 `remove_addr` 日志，在操作前提交并读回。重启时继续删除；若 Mesh 节点已不存在则直接恢复登记清理，清理完成后才释放日志和忙状态。日志存在期间忽略目标地址的业务包，避免旧 HELLO 重新登记。保留主机 PIN、其他从机和任务结果，原 PersistentState 格式不变。

删除前另存最后任务的地址快照 `result_addrs`，旧 FLOW 回放沿用旧地址；槽位复用后查询水量仍使用已持久化的任务结果。APP 将任务开始时的槽位与地址对应关系保存到手机历史，删除或复用槽位后不重新绑定旧任务；删除成功只清一次对应手机别名和当前调校状态。

## 验证边界

自动化覆盖：精确地址/阶段、离线超时、计时回绕、迟到回调、存储清理失败、重启恢复、只删除选中节点、活动任务拒绝、旧地址 HELLO、旧任务地址快照及 APP 旧固件兼容、确认门控和历史绑定恢复。

已完成主从机构建、host tests、APP JVM 单测、Debug APK 与 Android UI 测试源码编译。UI 测试和真实蓝牙删除尚未执行。验收需覆盖在线删除后重加、离线 LOCAL_ONLY、删除过程中断连/主机掉电、其他节点不受影响，以及槽位复用后的旧任务查询。

本功能不构成此前「新增从设备失败」或 Mesh 通信故障已经解决的实机结论。
