# Mesh 候选固件现场验收步骤

本手册当前对应[从机离线修复报告](SLAVE_OFFLINE_FIX_20261019.md)，原[实施报告](MESH_IMPLEMENTATION_ACCEPTANCE_20261019.md)保留历史版本。当前全部现场项目均为 **PENDING**。原始数据用同目录 CSV 记录；空表不代表通过。离线恢复的新增故障注入及受控重启条件见最新修复报告第 6 节。

## 1. 开始前填写的信息

准备1台ESP32主机、最多5台ESP32-C3从机、可重复的模拟流量输入/无水IO台架、受控水路、量杯或称重设备。逐台记录设备标签、Mesh地址、USB标识/端口、实际固件BIN SHA256、串口buildId、K/version、供电、水压及试验日期。确认500mL允许误差 `±____ mL`、测量分辨率及称重密度换算条件。

本机最近只读枚举为COM5主机、COM6从机、COM3/4蓝牙虚拟串口；连接变化后必须重新核对。主机工程默认COM3，不能直接使用该默认端口刷写。固件更新会重启设备，实水会驱动泵阀：由现场安排停机/水路/测量后执行。本次代码实施没有执行这些动作。

先备份当前固件/分区信息与NVS，确定format3回退恢复方法。不得为“清干净”擦除取消fence或防重放记录。混用旧从机时主机应拒绝新任务，这属于预期行为。

## 2. 候选校验与刷写顺序

1. 用包外 `.zip.sha256` 验证ZIP，用包内 `SHA256SUMS` 验证解压文件；记录 `candidate.json`。
2. 在输出关闭、无进行中任务时，先更新从机再更新主机。主机白名单仅接受本候选从机 `80ba7f64`。APK是未改变的debug候选，复用此前测试证据，先记录旧APP历史再按现场流程安装。
3. 应用地址两端均为 `0x20000`；引导地址主机 `0x1000`、从机 `0x0`；分区表均 `0x8000`。使用已核对的PlatformIO上传设置，或按 `candidate.json.flash_files` 制定实际烧写命令；不使用IDF辅助 `flash_args` 的0x10000。
4. 刷写后只查询身份/状态，核对 `hello` 主机 `build=4c3a56d9`、从机 `build=80ba7f64`、输出关、配网与commission状态。新设备先完成配网/配置，禁止为绕过协议拒绝取消白名单。
5. 换从机代码后先重建从机，取得完整manifest，审查并更新主机 `mesh_deployment.h`，再重建主机。旧ID不能复用为新固件身份。

## 3. 只读日志采集与统计

在主机目录开启全程采集，端口列表扩展为实际已核对的全部设备。下面只采集、不发查询/出水命令；打开串口的驱动行为仍需现场确认。

```powershell
& C:/Users/79622/.platformio/penv/Scripts/python.exe tools/capture_mesh_logs.py --port COM5 --port COM6 --seconds 600 --output dist/field-001.jsonl
```

在独立窗口/APP由现场执行本节之后的试验；结束后统计：

```powershell
& C:/Users/79622/.platformio/penv/Scripts/python.exe tools/analyze_mesh_logs.py dist/field-001.jsonl --output dist/field-001-timing.json
```

检查 `capture_errors=[]`、`capture_end`存在、`trace_lost=0`。采集停止时仍在途的ticket不能直接判为SDK漏回调；补足发送前后日志、boot边界和至少6000ms观察，再核实。采集器一次使用新文件，避免覆盖。8小时台架应采集至少28800秒并留启动/收尾余量，关注磁盘空间。

日志解释：`mesh_tx event=0`为commit、1为核心接受、2为拒绝、3为真实SAR end；`age`从commit前至该事件，含BTC调度，不是纯空口耗时。`wait`为入队至commit。`lease_rx matched=1/result=OK`给出匹配账本的ACK年龄；`applied=0`可能是先于accept暂存，不能一律当成无效。只读统计脚本不替代逐任务状态判断，也不自动给出硬件通过结论。

## 4. S0：先在无水/隔离执行器的设备验证SDK

执行下列矩阵，逐项记录故障注入方法、ticket、API结果、核心结果、end、实际占位与输出。需要可控的SDK/分配器/RTOS故障注入测试构建，使用独立身份；主机生产构建不得直接放入故障注入开关。

| 项目 | 设备通过条件 |
|---|---|
| API拒绝/host未启用/内存或BTC投递失败 | 不残留本地活跃SAR，不把拒绝当应用确认 |
| BTC ctx/data copy及buffer失败 | 无空指针/泄漏，恰好报告拒绝并进入预期保护 |
| 核心EBUSY/异步错误 | 首因可追溯，业务不自激重试、不无限占位 |
| 正常end/先于accept/重复/迟到旧ticket | 对应票据正确收回一次，不释放其他目的/新票据 |
| SAR超时/丢分段ACK | 有真实end才正常回收；明确错误停止，不按成功继续供水 |
| reset/reset_single/缺失end | 占位不假释放；6000ms冻结新发送，新任务拒绝；泵按更短授权期保护 |

主机与从机芯片都执行。离线提取桩已通过仍不能替代本节。若无法注入/观测某项，写明NOT_RUN及原因，不能勾选PASS。

## 5. S1/S2：1→2→5台模拟IO通信与保护

先使用本包生产并发1验收单路。**本包不能同时启用2/5路**；多路台架使用独立测试源码副本，在原`include/board_profile.h`将`MaxConcurrent`改为2或5并重建主机，保留修改、build.json、effective配置、完整BIN/ELF SHA256和专属试验日志。不要修改正在使用的生产源码/固件。若从机未改，仍应是白名单495431ba。测试构建不冒用本包e0950038，且不能使用强制生产并发1的打包工具给它签发同名候选包。

每一级通过后才进入下一级。每级先在模拟IO跑至少1000批、同步Hello/Summary突发和空闲切换，确认任务前能力检查、固定bootstrap、Opening证明、按节点单播与终态收尾。

记录SAR与LeaseAck的p50/p95/p99/max。初步性能目标SAR p99≤200ms、匹配OK LeaseAck p99≤800ms；同时检查每笔proof/start期限，不能用p99掩盖个别超时。主机业务峰值SAR≤2，从机≤1，同目的≤1；无`No multi-segment message contexts available`自激增长。普通SAR≤1，关键队列保留和在途不可抢占行为符合设计。

记录控制循环最大间隔、运行heap最低值/最大连续块、各任务栈高水位；当前静态RAM和`tick_max_ms`日志不等于完整运行内存证明，可用受控诊断构建/JTAG补测并保存其身份。任何不足必须整改/缩小batch后重新验证。

授权与安全测试逐项执行：

| 场景 | 核对点 |
|---|---|
| ACK延迟900/1100/1800/2500ms、跨轮/重复/错源/错job | 以issuedAt计龄；ACK重复不续命；不凭SAR end启泵；超限先停 |
| 4台正常+1台900ms慢节点/遥测阻塞/丢数据或SAR ACK | 不增加窗口、不拉长Lease/NoFlow；有界失败或停止；队列不累积 |
| Target状态与在途Lease乱序 | 从机已关阀时回真实Status；正常Target不伪造授权；已记录主机abort不被抹掉 |
| 队列满时停止/停止与dispatch同时发生/Close丢失 | 本地停泵不等Mesh；屏障后不commit旧授权；远端按最后有效租约保护关闭 |
| 首个Start至启泵和首脉冲 | bootstrap固定2400ms；每路实际Start至启泵+建压首脉冲+调度余量<5000ms，余压情况下也满足1500ms无新增脉冲保护 |
| 主/从重启、各持久化点断电、手机断连重连 | 输出默认关，无自动重跑；fence保留，查询原任务；未知保持unknown；原因与现有持久化证据一致 |
| 旧端/未知build/错误nonce/rev/features | Start前拒绝，泵不启动；不降级跳过检查 |

保护故障试验的“通过”表示正确停止；它不是一批正常出水成功。已进入SDK的授权可能迟到，远端3000ms从最后有效租约接收计，不承诺点击停止后固定3秒物理阀关闭；无物理阀位反馈时只验输出并另测尾流。

## 6. S4：实水计量与8小时台架

完成前述设备通信/保护门槛，再按1路20次、2路20批、5路20批做500mL试验。多路每一批记录每一路，共160条水量记录。每条保留job、设备、关阀脉冲、最终脉冲、尾流、量杯/称重、主机停止原因、从机原因、quiet/truncated和原始日志路径。使用 `MESH_FIELD_ACCEPTANCE_20261019.csv`，不得以设备自报mL替代独立测量。

正常样本要求从机Target、quiet Done、无truncated，主机无abort且所有所选结果可确认。最终脉冲允许包含关阀后的尾流，不要求恰好2940；按已约定物理容差判定每路。故障样本单列，不自动补抽。只有正常结束后仍有稳定偏差，才安排K标定/尾流补偿实验，本次没有擅改K。

5台完成至少8小时墙钟模拟IO台架，覆盖周期任务、空闲、后台发现/恢复和断连；记录起止时间、批次数、最小heap、栈高水位、队列/ticket峰值、最终归零和所有保护触发。8小时虚拟仿真报告不计入该时长。部署在线节点超过5台时按真实登记/订阅数量另测，不能外推。
